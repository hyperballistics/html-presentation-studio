# HTML Studio：可移植的 HTML 演示工作区

## 运行前准备

- **必需：Node.js 22 或更新版本。** 如果还没安装，请从 [Node.js 官网](https://nodejs.org/en/download)选择符合要求的 LTS 版本。启动命令使用 `npm`，通常随 Node.js 一起安装。安装后重新打开终端，确认下面两个命令都能输出版本，并且 `node` 的主版本号不低于 22：

  ```sh
  node -v
  npm -v
  ```

  如果提示找不到命令，先确认 Node.js 和 npm 已安装并在终端的 `PATH` 中；如果 Node.js 版本低于 22，先升级或切换版本。
- **必需：一个可打开本机网页的浏览器。** 用它打开工作台即可编辑、播放审阅和导出 HTML；它不必是下文用于 PDF 直出的浏览器。
- **不用安装项目依赖。** 没有第三方 npm 运行时依赖，不用执行 `npm install`。字体随包提供，不用装到系统里。单独使用工作台不需要 Agent 客户端、Skill、MCP 或 API Key。

### 首次启动

1. 解压发行包或取得完整源码。在终端进入包含 `package.json` 的目录；用 npm 发行包时通常是解压后的 `package/`。
2. 在该目录运行 `npm run check`，检查清单、页面与字体。通过后运行 `npm start`。
3. 保持终端运行，用浏览器打开终端显示的地址（默认 `http://127.0.0.1:4377`）。不要双击打开 `workbench/index.html` 来启动编辑器。若 4377 被占用，可改用 `npm start -- --port 4378`，再打开新地址。服务只监听本机，不对局域网或公网开放。

如果要写回源文件或同步上下文，请把项目放在当前用户可写的目录。开发者可另用 `npm test` 跑自动化测试；它不是启动前置步骤。

### 可选：配置 PDF 直出

内置「导出 PDF」的直出功能和命令行 PDF 导出都由 Studio 调用本机浏览器完成。只编辑、播放或导出 HTML 时，可以跳过这一步。将下列任一受支持的浏览器装在对应位置，程序就会自动查找：

| 系统 | 自动查找的浏览器位置 |
|---|---|
| macOS | 在 `/Applications` 和 `~/Applications` 下查找 `Google Chrome.app`、`Microsoft Edge.app`、`Chromium.app` 中的 `Contents/MacOS/<浏览器名>`。 |
| Windows | 在 `%ProgramFiles%`、`%ProgramFiles(x86)%`、`%LOCALAPPDATA%` 下查找 `Google/Chrome/Application/chrome.exe` 或 `Microsoft/Edge/Application/msedge.exe`（路径分隔符也可写为反斜杠）。 |
| Linux | `/usr/bin/google-chrome`、`/usr/bin/chromium`、`/usr/bin/chromium-browser` 或 `/usr/bin/microsoft-edge`。 |

当前不会搜索 `PATH`，也没有自定义 PDF 浏览器路径的配置项。如果终端报 `renderer-not-found` 或 `find-renderer`，先确认浏览器在上述位置，并且当前用户可访问和运行。只把浏览器加到 `PATH` 不会解决这个问题。

可以用 `npm run export -- pdf --out ./studio-smoke.pdf` 测试直出，输出文件名必须尚不存在。不便安装时，可在工作台选择「导出 PDF」→「浏览器下载」，在回退的打印对话框选「保存为 PDF」；打印回退的纸型设置可能与直出不同。

## 试一页

包内预置一页可运行示例，方便验证编辑、草稿和导出。它不是项目需求或正式案例；新项目按下文替换自己的内容指针。

1. 双击画布文字，或从右侧属性修改字体、字号、字形、对齐、文字色。矩形支持像素圆角；形状支持独立填充、边框颜色和粗细（0 = 无边框）。点击色块打开颜色选择器，点「取色」吸取屏幕颜色；系统吸管不可用时，可点画布对象取样式色、点空白取背景。在左侧大纲、右侧属性的标题处可分别折叠；大纲内「页码」和「图层」也可点横条独立收起。刷新保留状态。在桌面视口可拖动大纲和属性栏靠画布的内边界来调整宽度；刷新或折叠后保留宽度偏好，窄视口沿用原布局。
2. 修改会自动存为**当前浏览器本地草稿**，刷新可恢复；不会静默覆盖 HTML。点第二行工具栏的「写回源文件」审阅差异，确认后才原子写入，旧版备份在 `.runtime/history/`。草稿不能通过复制项目迁移；共享前请先写回，或导出。
3. 若另一处改了源文件，旧草稿仍在，但 412 阻止覆盖。冲突面板可先导出草稿，再加载新源。它不自动合并。打开多个标签页时尽量不要同时编辑同一页；检测到本地草稿冲突会为当前标签页另存备用草稿，刷新同一标签页可找回。
4. 「导出 HTML」输出当前草稿/源状态的离线单页，内嵌字体、许可证，约 19 MB。包内实体 HTML 本身较小，显示依赖同包字体，可用工作台继续编辑。

### 工具栏键盘操作

`Tab` 进入对象工具栏后，用 `←` / `→` 移动焦点，`Home` / `End` 跳到首尾，`Enter` / `Space` 执行当前按钮。再按 `Tab` 继续到「写回源文件」「同步上下文」。画布上的方向键仍用于微调对象位置。

### 页面尺寸与视图缩放

- 在画布上方的「页面规格」选择屏幕比例：16:9、4:3、16:10、3:2、1:1、9:16、21:9。亦可选 **20 种纸张规格**：ISO A0–A6、ISO B0–B6、JIS B4/B5、Letter、Legal、Tabloid、Executive；纸张可另选横向或纵向。ISO 与 JIS 的 B4/B5 不是同一尺寸，菜单中分别列出。
- 页面规格逐页保存，可在同一演示混用。更改规格先存本地草稿，写回时会显示差异。内容放得下就保留原尺寸；放不下时从左上角等比缩小，保留组合与箭头连接（最小对象和文字尺寸仍生效）。可撤销；切回较大纸型不会自动放大。新页沿用同节末页的已写回规格，空节参考演示首个已写回页面。旧页没有 `format` 字段时仍为 1280×720（16:9），无需迁移。已写回非默认规格的页需用支持该字段的版本打开。
- **− / ＋** 调节画布缩放，点百分比恢复 **100%**，点 **适合** 自动匹配窗口。放大后用画布滚动条浏览。缩放只改变编辑视图，不改对象、草稿或导出；审阅始终适合屏幕。
- HTML 保留相应画布尺寸；本机 Chromium PDF 导出支持逐页纸型和方向，允许同一 PDF 混用。浏览器打印回退可能受浏览器与打印设置限制；需保留混合纸型时优先用内置/CLI PDF 导出。

### 播放审阅与动画

点「播放」进入独立审阅模式，从正在编辑的页开始。该模式不编辑、不自动播放，可手动翻页、全屏和导出。用 `←` / `→` 或 `Page Up` / `Page Down` 翻页，按 `F` 切换全屏；退出全屏后再按 `Esc` 返回编辑。如果客户端的内嵌浏览器禁止系统全屏，则只铺满客户端视口；真正投屏时请用独立浏览器打开本地地址。

在「属性 → 动画」展开设置。**切换动画**可选无、淡入、滑入或缩放进入。**点击动画**可选无、直接出现、淡入、上浮进入或缩放进入；对多选或组合设置时，这些对象在同一步出现。步骤按添加顺序排列；改同一步的效果不调序，删除后重建或重新分配对象会将新步骤放到队尾。审阅时点击画布、按 `Space`（焦点不在按钮时）或点「下一动画」，一次显示一步；再次进入同一页会重置。显式翻页键和按钮可直接跳过剩余动画。启用系统「减少动态效果」时只做即时切换与出现。编辑、缩略图与 HTML/PDF 导出始终显示所有对象。

**审阅版本**：播放与整套 PDF 都可能包含草稿，不是已写回版本的校样。非当前页的本地草稿只要能通过模型校验，就优先于源文件使用，即使源后来有更新。若要核对已写回版本，请在没有该项目草稿的浏览器环境中审阅。

### 选择导出位置

点击「导出 HTML」或「导出 PDF」，在小窗选择保存方式。**选择保存位置…** 会打开系统「另存为」，可当次选择文件夹和文件名；取消不会启动导出。该选项取决于浏览器支持，内嵌浏览器未必允许。也可以选择「浏览器下载」：要每次询问保存位置，需打开浏览器的同名下载设置。没有本机 PDF 渲染器时，「浏览器下载」可回退到打印对话框并选择「保存为 PDF」。PDF 不含讲者备注或界面。

若有常用交付目录，启动时配置以下快捷选项：

```sh
npm start -- --port 4378 --export-root "/绝对路径/交付目录"
```

目录须提前创建，并对启动工作台的用户可写。小窗会额外显示「保存到导出根目录」及绝对路径。使用这个选项会生成独立单页 HTML 或按清单顺序合成的 PDF；重复操作生成不同文件，不覆盖旧件。根目录由启动者指定，浏览器和 Agent 不向服务传写入路径。目录移动、失效或根目录导出渲染失败时会报错，不会改存到别处。

界面导出可以包含浏览器草稿，不写回实体。工作台能显示服务端写入的绝对路径；系统「另存为」只向工作台提供文件名。发布已写回版本请用下文的 `--out` 命令。

### 框选、组合与快捷键

- 从画布空白拖框，选中与框相交的对象。画布和图层选中同步；按住 `Shift`（也可用 `Ctrl` / `⌘`）点击对象或图层可增减选择，`Shift` 拖框可追加，`Ctrl/⌘+A` 全选。页面没有空白时，可直接在图层中加选。
- 多选后点「组合」（`Ctrl/⌘+G`）；选中任一成员就选中整组。「取消组合」（`Ctrl/⌘+Shift+G`）恢复独立选择。拖任一选中成员移动，拖选框右下角等比缩放，也可在属性输入选区位置和尺寸。组合不改变层序，组内成员仍可在图层中单独排序；已连接的箭头端点始终跟随对应锚点。
- 属性栏只显示多选成员共有的设置。批量改样式不会覆盖各自的文字，文字和箭头端点仅能单独编辑。部分样式值不同时，修改某项会把该项统一应用到选区。
- 按 `Backspace` / `Delete` 删除选区，`Ctrl/⌘+C` / `Ctrl/⌘+V` 复制和粘贴。粘贴生成新 ID，保留所复制的组合与内部连线；指向未复制对象的端点转为自由点。变换可撤销，组合和动画随草稿自动保存。文本与属性输入框保留原生编辑快捷键。

### 页码与分节

在「大纲 → 页码」点「＋ 分节」新增分节，点分节标题折叠或展开，刷新后保留。分节右侧可以新增页面、改名或移除空分节；移除不会删目录和文件。拖动页面右边的手柄可在**同一分节内**排序（键盘可在手柄上按 `Alt+↑` / `Alt+↓`），不会改已有页 ID 或文件路径。新增和排序直接保存清单，旧清单保存在 `.runtime/history/`，不写回画布草稿。

浏览器与 CLI 新增页面都创建独立 HTML、备份旧清单和索引，并同步新增 `STORYLINE.md` 页行。拖动时同步索引行序，不自动改叙事文案。索引的页行必须在一张连续的表内，使用一致的换行、按清单顺序排列；新增或调序后仍需由作者复核内容和承接。不要在服务运行时从其他客户端手改清单或索引。

**中断恢复**：单文件发布是原子的，页面、索引和清单不是一次原子提交；失败不会自动删除未登记的页或分节目录。先停止服务并保存现场副本，对照 `.runtime/history/` 中的 `manifest.*.json`、`storyline.*.md` 核对最后匹配的清单与索引；若不一致，先在副本恢复成匹配的一对并运行 `npm run check`。该检查不扫描未登记资产。若显式 ID 的 CLI 新页已落盘但未登记，索引与清单恢复一致后可同参重试，仅复用字节完全相同的实体；内容不同不覆盖。浏览器重试会生成新 ID，原有未登记资产留待人工比对处理。

### 图层排序

拖动大纲中图层右侧的手柄调整叠放顺序，列表上方对应画布前方。也可以选中图层后用「上移一层／下移一层」，或聚焦手柄后按 `↑` / `↓`。重排可以撤销，并会随草稿保存。

### 箭头连接

点「箭头」插入，拖动「起 / 终」到对象边缘中点，蓝色圆点表示可吸附。也可在右侧选择连接对象和上、右、下、左锚点，或输入自由端点的 X/Y。移动或缩放相连对象时箭头随动；拖到空白可断开连接，删除目标则保留原位置为自由端点。箭头可改线色和粗细、参与撤销与导出。当前使用直线，不自动绕障碍。

## Agent 使用

换机器或换 Harness 时，按 [跨 Harness 部署](agents/deployment.md)打包、迁移和校验。项目可以独立运行，但目前不自动安装成客户端原生 Skill。

Agent 不占用编辑界面的侧栏。用 **OpenCode / Codex / Claude Code / ZCode** 打开这个目录，在相应客户端的终端运行 `npm start`，从客户端自带浏览器或外部浏览器使用工作台。规则仍共用 [AGENTS.md](AGENTS.md)；需要结构化单对象交接时，使用 [Agent 命令与协议](agents/protocol.md)。工作台不启动客户端、不要求 API key，也不自动采纳提案。

### 写回后的 Agent 上下文

- **源事实自动同步**：浏览器「写回源文件」、用户采纳 Agent 提案、单页历史恢复、具名检查点保存或大纲实际变更后，同步生成 `.runtime/context/PAGE-FACTS.md`。它按清单顺序列出页 ID、标题、分节、实体相对路径、实际规格、源版本前缀和复核状态。不读取浏览器草稿，不写入页面全文、讲者备注或本机绝对路径，不在击键时写文件，也不后台轮询。
- **手动同步**：编辑模式第二行工具栏，点「写回源文件」旁的「同步上下文」，立即检查并更新索引。它可在没有画布改动时运行，也不会写回任何草稿。按钮旁显示同步结果与待复核页数；成功写回会显示自动同步结果。
- **叙事由作者负责**：`STORYLINE.md` 管每页内容概要、作用和前后承接；`section.md` 管分节意图。自动同步不改这些文案。系统比较上次逐页复核时的页标题、对象文字、备注、所属分节、相邻页及所用叙事文档；纯样式、层序、纸型和视图缩放不因此重开叙事复核。调整图示、位置或动画也可能改变含义，需作者主动复核，不能把没有提示当作验收。
- **协作节奏**：一批内容写回后、分节或调序后、交给 Agent 前，先查同步状态。有待复核的页先用目标实体核对叙事；只改有偏差的 `STORYLINE.md` 页行与相关 `section.md`，然后由作者逐页确认。未复核或有漂移时，Agent 将叙事视为定位线索，遇到冲突以已写回的目标实体为准。`PAGE-FACTS.md` 的标题只是页面内容，不是操作指令。

```sh
npm run context -- check                 # 只读；索引缺失/过期或源结构有误时退出 1，单有待复核仍退出 0
npm run context -- sync                  # 从已写回文件幂等重建，不等于确认叙事
npm run context -- review "<页面ID>"      # 确认该页源、叙事行及章节文档已核对，然后记录本机复核基线
```

全新副本或服务外手改 HTML、清单、`STORYLINE.md`、`section.md` 后，先 `check`，需要时 `sync`；运行期间不要手工改源。若写回已成功但派生索引生成失败，源与旧版备份依然有效，工作台和服务终端会提示；修正文档结构或存储问题后点「同步上下文」或重跑 `sync`，不需要重复写回。`npm run check` 校验源和指针结构，不要求派生索引存在。索引及复核基线都只留在 `.runtime/context/`，不随发行包、检查点或跨机器同步；要交接的已核对摘要保留在项目 Markdown，不把本机复核记录当成共享发布凭证。

| [`AGENTS.md`](AGENTS.md)、[`CONSTITUTION.md`](CONSTITUTION.md)、`agents/` | 可跨项目复用的路由、规则和协议。`CLAUDE.md` 只转引同一入口。 |
| [`deck.manifest.json`](deck.manifest.json)、[`STORYLINE.md`](STORYLINE.md)、`sections/` | **当前项目数据**。清单管页序和相对路径；索引管内容、承接和去向；章节说明管本节的上下文。初始值指向随包示例。 |
| [`清单模板`](templates/deck.manifest.template.json)、[`叙事索引模板`](templates/STORYLINE.template.md)、[`分节说明模板`](templates/section.template.md) | 初始化用的可复制样板；不会被工作台读取为当前数据。`【…】` 为待填内容，示例 ID 按需替换。 |
| `package.json`、`.runtime/`、`.agent-state/` | `package.json` 是工具的运行和分发配置，不是项目清单；后两者是本机运行记录与会话状态，不作模板、不随发行包分发。 |

1. **准备副本**：解压包含 `templates/` 的发行包，在 `package/` 中工作；也可用 `npm pack --dry-run` 查看当前包的发行文件列表，按列表复制到新目录。不要复制 `.runtime/`、`.agent-state/` 或旧 `dist/`；分发时保留包内字体许可证。
2. **创建自己的分节和页**：先停止编辑服务。按分节说明模板创建 `sections/<分节ID>/section.md` 与同级 `pages/`；在当前清单中按模板追加该分节，先写 `"pages": []`。保留示例页直到新页登记完成，工具要求清单至少有一页。以下命令中的占位值需替换：

   ```sh
   npm run new -- "<分节ID>" "<页面ID>" "<页面标题>"
   ```

   该命令生成独立实体并同步清单和索引；同分节、ID 和标题重跑不覆盖已有页。分节 ID 用小写字母、数字、连字符；页 ID 还须以小写字母开头。ID 最长 60 字符，路径必须与 ID 一致。
3. **切换当前指针**：按叙事索引模板补齐各页内容与承接，页行与清单顺序一致。更换项目标题后，如果不需要随包示例，从清单去掉示例分节、从索引去掉同一页行，再运行 `npm run check`。这不删除实体文件；未登记目录仍可能被打包，分发新项目副本前应检查 `npm pack --dry-run` 的文件列表。

实体内唯一可维护数据是 `<script type="application/json" id="slide-model">`；正文是 `workbench/model.mjs` 生成的显示投影，不是第二份维护源。工作台按清单加载页面，不把任意旧 HTML 当作可编辑实体。`tools/workspace.mjs` 负责版本校验、备份和写回；仅适用于可信本机单实例，不对公网提供服务，不让浏览器或 Agent 提案传入任意写入路径。

**当前界限**：不是 PPTX 读写器，不支持局部字符富文本、媒体/任意 DOM 导入、跨浏览器草稿同步、实时多人协作或自动调用 Agent。对象模型及协议刻意保持小且可验证。

## 参考与取舍

- [Chrome File System Access](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)：从用户点击直接打开系统「另存为」，拿到授权文件后才渲染和写入。不支持时保留显式下载或预设根目录。

- [CSSWG Media Queries Level 5：`prefers-reduced-motion`](https://drafts.csswg.org/mediaqueries-5/#prefers-reduced-motion)：只在 `no-preference` 时启用短淡入；减少动态效果不改变审阅顺序或内容。

- [GrapesJS Storage Manager](https://grapesjs.com/docs/modules/Storage.html)：借鉴“结构化编辑数据≠显示 HTML”，不依赖反解 DOM；本包把模型和投影收在一个页实体里，迁移不掉数据，不引入编辑器框架。
- [HTTP If-Match（RFC 9110）](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-match)：用强版本条件防止旧写覆盖新版本，而不是比较客户端时间。
- [OpenCode 指令](https://opencode.ai/docs/instructions/)、[Codex 项目指令](https://developers.openai.com/codex/guides/agents-md)、[Claude Code 项目记忆](https://code.claude.com/docs/en/memory)：共用一份短 `AGENTS.md`；Claude Code 提供导入入口。ZCode 以显式文件提示兼容，不宣称其特定版本会自动发现规则。
- [视觉标准、默认主题与字体资产](agents/design.md)。

## 指定路径导出已写回版本

在项目根运行；`--out` 可用绝对路径，或相对发起命令的目录。省略 `--page` 时按清单导出全部页。

```sh
npm run export -- html --out "./exports/pages"
npm run export -- html --page "<页面ID>" --out "./exports/one-page"
npm run export -- pdf --out "./exports/deck.pdf"
```

- HTML 以 `页ID.html` 一页一文件输出。整批共用 `fonts/`（含许可证）；`export-manifest.json` 最后写入，记录页序与哈希。搬运时保留整个目录。相同完整导出可重复执行且不改写；其他既有目录不覆盖。中断时 CLI 会给出目标绝对路径和失败原因；该目录可能留有未完成文件，不会自动清理，请另选目录重试。重试时会区分清单缺失或不同、文件缺失或哈希不匹配，以及读取错误。
- PDF 合成一个文件，依赖[本机 PDF 渲染器](#可选配置-pdf-直出)；目标须为新 `.pdf` 文件。渲染失败时在启动工作台的终端或 CLI 输出查看 `[PDF] stage=…` 和相关错误码、退出码或信号；浏览器不显示本机诊断细节。命令行失败时可用界面的打印回退，但须先确认草稿状态。
- 两种命令都只读实体源，不读取浏览器草稿、不改项目，省略讲者备注。CLI 输出路径由人显式指定，不向浏览器或 Agent 提案开放任意路径写入能力。

## 保存、检查点和大版本

| 层 | 保存时机与位置 |
|---|---|
| 浏览器草稿 | 自动保存于当前浏览器。不为每次编辑增加文件历史或发行号。 |
| 源文件小修 | 实体确有变化时，先验证并保存旧版到 `.runtime/history/` 再写回。备份以 ID 和内容哈希标识；重试若结果已是当前源则不再写入。 |
| 具名检查点 | 需要审阅、迁移或回退时使用。`.runtime/checkpoints/` 只写索引，不同检查点复用内容相同的历史对象；不保存字体、缓存或 PDF。 |
| 发行版本 | 新版本在隔离副本中更新代码与 `package.json`，验收后才打包。包是可执行工具的快照，检查点是可恢复内容的快照，两者不能互代。 |

```sh
npm run history -- checkpoint before-update
npm run history -- list
npm run history -- verify before-update
# 先处理浏览器草稿、停止服务。用当前实体 HTML 的 SHA-256 作预期版本：
npm run history -- restore before-update <页面ID> sha256:<当前64位十六进制哈希>
```

`verify` 可独立核验索引和源快照，即使当前实体已丢失。`restore` 只恢复当前清单可映射且渲染兼容的单页，也会备份恢复前的页。清单、叙事或格式不兼容时，在副本中用相应旧发行包和检查点迁移；不自动覆盖整套源和旧草稿。手工新增或调序时须同步 [`STORYLINE.md`](STORYLINE.md)；工具会同步页行，但仍须复核叙事并运行 `npm run check`。

**发布门槛**：保存迁移前基线并核验 → 在副本中更新版本、验证旧页/草稿/提案是否兼容 → 验收候选并留发布检查点 → 在新目录打包并解包复测，记录发行号、检查点、归档 SHA-256 和验证结果。不要重打或覆盖同号发行品。兼容修复用补丁号；新功能用次版本；不兼容变更先写清迁移、回退和兼容窗口，再确定大版本。只归档验收后的发行物；不要把 `.runtime` 打进发行包。版本号原则参考 [SemVer](https://semver.org/)，不强求把每次内容编辑都当软件发行。

**保留与恢复**：默认不清理；按需用 `list` 查检查点和历史对象数。重要检查点保留索引及其引用历史并另存一份；空间不足时先清可再生的导出/缓存，不自动删备份。`.runtime/locks/write` 仅用于协作写入；异常终止后若见残留锁，先确认所有写入进程已退出并备份 `.runtime`，再由维护者处理空锁目录。不能保证正在用外部编辑器硬写同一文件时的多写者事务。
