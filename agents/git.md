# Agent Git 维护原则

适用于维护本仓库历史和远程分支的 Agent。操作范围遵循用户授权与远程分支规则，项目文件的维护边界以[项目宪法](../CONSTITUTION.md)为准。[项目入口](../AGENTS.md)规定的单对象提案流程仍只交付提案。

## 开工与选分支

- 先用 `git status --short --branch` 核对当前分支、工作区和暂存区。涉及远程发布时，再核对 `git remote -v`、上游和目标分支，获取远程最新引用后检查分支差异。保留用户已有改动和暂存范围。同一文件内难以分开时，先请用户确认归属。
- 低风险、范围清楚的说明文档改动，在用户已授权推送且远端允许时，可以直接在当前 `main` 做普通快进发布。功能、模型或协议兼容性改动，以及需要协作者审阅的变更，优先使用短期 `codex/<简短主题>` 分支。获授权后开 PR，说明变更、验证结果和剩余风险。分支保护和必需检查始终优先。

## 提交与一致性检查

- 按可独立审查和回退的目的组织提交。提交标题简明描述改动，正文按需记录动机、兼容影响或迁移。只暂存明确归属本任务的路径或片段，提交前检查 `git diff --cached`、`git diff --cached --check` 和未跟踪文件。
- 目录说明统一用 `README.md` 的「用途」「主要内容」「维护边界」三节。用相对链接指向现有文件、上级入口或权威索引。源文件、叙事索引、清单、模板和文档各自按项目契约维护，避免说明和权威记录产生冲突。
- 验证贴合变更。文档核对链接、目录覆盖和约定一致性。模型、页面或工具跑 `npm run check` 与 `npm test`。UI 或布局变更还要检查实际浏览器渲染。记录实际结果及未验证的项目。推送前发现一致性或相关验证失败，先修复并复查。
- 仅发布适合进入版本历史的文件。凭据、私密数据、浏览器草稿、`.runtime/`、`.agent-state/`、依赖目录和生成的发行物留在本机。`.gitignore` 只作为辅助，已跟踪内容仍须查暂存差异。发现已外泄的凭据时先撤销或轮换，再由维护者协调后续清理。

## 推送与恢复

- 提交、推送、开 PR 和合并各按任务授权执行。推送前确认待发布的全部提交均在范围内、目标仍允许快进，并检查工作树和暂存区状态。推送后用 `git ls-remote` 核对目标分支提交，交付分支、短 SHA 和验证结果。
- 远端领先、分叉或拒绝推送时，先获取最新引用并检查提交差异，按仓库的分支规则处理。保留用户改动和钩子检查结果。已发布的问题优先用新修复提交或 `git revert`。重写共享历史、强推、删远端分支或丢弃本地修改，需要针对具体影响另行授权。
