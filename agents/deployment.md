# 跨 Harness 部署

**现状：可部署独立工作区，尚无一键部署命令，也不自动注册各客户端的原生 Skill。** 工作台和 Agent 规则一起随包迁移；客户端的账号、权限和全局配置由使用者管理。

## 1. 在源工作区准备发行包

1. 若要迁移现有内容，先在原浏览器审阅并点「写回源文件」，核对 `deck.manifest.json`、`STORYLINE.md` 和相关的 `section.md`。未写回的浏览器草稿不会迁移；备份、检查点和上下文复核记录也不随发行包走。
2. 在源包根目录运行 `npm run check`，再运行 `npm pack --dry-run`，核对实际将纳入归档的文件。随包保留字体与许可证；排除 `.runtime/`、`.agent-state/`、`dist/`、缓存、导出件和本机配置。文件在 `sections/` 中即使未登记到清单，也可能被打包；对外分享前另行确认页面、素材和源码的分发授权。
3. 从已验收的源码打包到一个**已存在的空输出目录**，不要覆盖同版本发行物。把占位符换成实际目录：

   ```sh
   npm pack --pack-destination "<发行输出目录>"
   ```

   使用终端实际输出的归档名，不把 `dist/` 当作当前版本的来源。正式发行按 [README 的发布门槛](../README.md#保存检查点和大版本)记录版本与归档 SHA-256，并做解包复测。

## 2. 在目标 Harness 中使用

1. 安装 **Node.js 22+**。将 `.tgz` 解压到用户指定的**新空目录**（可用 `tar -xzf "<发行包路径>" -C "<目标目录>"`），不要向已有工作区合并解包。
2. 在目标客户端打开解包后包含 `package.json` 和 `AGENTS.md` 的 `package/` 目录。在该目录中运行：

   ```sh
   npm run check
   npm run context -- sync
   npm start
   ```

   校验失败则先停止，不启动服务。`context -- sync` 从已写回源重建本机事实索引，不确认叙事。工作台无需 `npm install`、MCP 或工作台 API Key；仅在本机回环地址运行一个服务实例。用浏览器打开终端打印的地址；内置 PDF 直出另需本机 Chromium。
3. 按 [Agent 交接协议的客户端入口表](protocol.md)加载规则：Codex / OpenCode 使用 `AGENTS.md`；Claude Code 有 `CLAUDE.md` 转引；ZCode 显式让 Agent 读取 `AGENTS.md` 和 `agents/protocol.md`。自动加载不可用时，也可使用显式提示。确认 Agent 读到的是目标包，而非父目录或原工作区的规则。

**验收分开记**：解包后的 `npm run check` / `npm test`、浏览器打开示例页、目标客户端实际加载规则是三件不同的事。未亲测的客户端不要记为已通过。

## 3. 后续一键部署的要求（尚未实现）

- 输入已验收的发行包、用户指定的新目录和可选的目标 Harness；检查 Node 版本和目标路径，不覆盖已有项目，不将失败残留当作成功部署。
- 解包并校验后，输出目标包根目录、`npm start` 启动方式和对应的 Agent 入口；默认不启动服务、不复制源机器运行态、不修改客户端全局配置。
- 原生 Skill 注册是独立步骤。只有用户明确要求、目标客户端和版本已确认时，才按该客户端支持的方式配置并验证加载。包内 `skill/` 是 Codex Skill 构建模板，不是四个客户端通用的安装器。
